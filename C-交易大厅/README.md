# 方案 C「交易大厅」

AI 电商的**交易报价板**。参照系是彭博终端、机场航班信息牌、交易所大厅的报价屏 ——
金融终端的视觉语言自带「这是真金白银」的暗示。

零 3D、零粒子、零 canvas 绘制（canvas 只在启动时量一次字体度量）。全部预算花在
**排版精度**和 **split-flap 的机械质感**上。

```
C-交易大厅/
├─ index.html    结构 + 全部 CSS
├─ app.js        classic script（无 module / 无 fetch / 无网络 / 无 Math.random）
└─ README.md
```

## 1. 设计意图

### 三层阅读结构（对应规格 §4.5 的 5 秒法则）

| 距离 | 看到什么 | 承载元素 |
|---|---|---|
| 5–10 m，0–1 s | 一个巨大的数字在动 | `metrics.crawls` 数字轮，字高 192px |
| 3–5 m，1–3 s | 读懂主语与单位 | `CUMULATIVE AI CRAWLS · AI 累计抓取` + 右侧仪表列 |
| 1–3 m，3–5 s | 「有人下单了」 | 磁带每来一单，整行字符逐列机械翻页落位 |

冲击力押在**体量与运动**（数字轮 + 全表齐翻），高级感押在**颜色与密度收敛**
（P2 暖墨陶土，全屏只有排版和 1px hairline，零边框 / 零发光 / 零渐变 / 零扫描线）。
公开数据走 `--panel` 浅底带，模拟数字走深底，视觉分区，不让真数据给假数字背书。

### split-flap 怎么做的

- **字符格网格**：每行 115 个固定宽度的 `span`，绝对定位在 `i × SLOT`。
  `SLOT` 不是硬编码的 —— 启动时用隐藏探针量出等宽字体的实际字宽
  （Consolas 0.55em / Cascadia Mono 0.60em / 回退字体又不一样），再反算出
  「刚好装满 1688px」的字号。**列对齐因此不依赖任何字体假设。**
- **对象池**：10 行 × 115 格 = 1150 个 span 常驻，只改 `textContent` 与 `transform`，
  全程不 append / 不 remove。顶部插入靠环形缓冲改 `translate3d`，
  被淘汰的那一行「无过渡」跳到顶部再翻入，不会出现一行从底飞到顶的鬼影。
- **翻页鼓面**：每格只在同类字符里翻（数字鼓 / 字母鼓 / 标点鼓），跟真实机械牌一致。
  逐列 stagger 21ms，每格翻 3~5 次，落位即清 transform。
  下落用 `rotateX(-76° → 0°)` 加速到 0（`1 - p²`），落地即停，**没有回弹**。
- **全角字符占 2 格**：日文商品名的每个字占两个格位（字形溢出到右边那个空格里），
  所以 JP 行和 US 行的 `CC / USD / AI REFERRER` 列**严格对齐**，不会被 CJK 顶歪。
- **声音**：每翻一行只响一次 `APAudio.blip()`，订单本身走 `APAudio.playOrder()`。
- **里程碑齐翻**：全表 10 行同时起翻、按**列** stagger，一道乱码波从左扫到右 2.2 秒扫完。
  因为目标内容 = 当前内容，所以还没轮到的列显示的仍是正确内容，只有波峰是乱的。

### 列定义（合计 115 格，代码里有断言）

```
格位  0    2        12                       38  43                                    82         94
      *  ▏时间     ▏店铺(24)                ▏CC▏商品(37)                             ▏金额(10) ▏来源(21)
      *  19:57:26  RIVER GROVE               US  LINEN CANVAS DESK LAMP                $ 1,157.00 CHATGPT.COM
```
金额走**会计式**：`$` 钉在字段首格，数字在余下 9 格右对齐。店名 / 商品超长截断加 `…`，绝不换行。

## 2. 快捷键

| 键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续 |
| `M` | 静音 / 取消静音 |
| **`B`** | **人工触发一个大单**（金额锁死在 epic/legendary，必然高亮 + 人声） |
| `N` | 触发一个普通单 |
| `K` | 里程碑庆祝（全表齐翻 + 大字） |
| `1` `2` `3` | 速率 ×0.5 / ×1 / ×3 |
| `G` | 调试网格（等同 `?debug=grid`） |
| `H` | 展馆音频模式 |
| `A` | 环境音床 |
| `F` | 全屏 |
| `R` | 重置 |
| `?` | 快捷键图例 |

启动遮罩点击时执行 `APAudio.unlock()`。
`?nogate=1` 只给 QA / 自动截图用（跳过遮罩，音频不会解锁），**现场演示不要用**。

## 3. 已知取舍

按重要性排序。每一条都是权衡后的选择，不是没做完。

### 3.1 巨型数字字高是屏高 17.8%，不是 30%

几何上做不到。引擎的 `CRAWLS0 = 420,000,000`，所以 `metrics.crawls` 是
**9~10 位数**。10 位 + 3 个千分位间隙要装进第 1~9 栏的 1258px：

```
字号 ≤ 1258 / (7×0.467 + 3×0.467×0.60 + 0.62em) = 266px  →  字高 192px = 屏高 17.8%
```

要做到字高 324px（30%），10 位数需要约 2400px 宽 —— 比整块屏还宽。
**在「右侧带仪表列 + 下方带 10 行表」的 16:9 版面里，30% 不存在解。**
换取的方式是：全屏除巨型数字外没有任何字号超过 46px，所以它仍然是绝对主角。
（真要 30%，得砍掉右侧仪表列让数字占满 1688px，字高约 209px = 19.4%，仍到不了 30%。）

### 3.2 读数按 10 取整（个位轮恒为 0）

`crawls` 以约 48 次/秒增长。个位轮 = 48 格/秒 = **每帧 0.8 个节距**，超过半个节距，
60Hz 采样下必然出现车轮效应 —— **数字看着往回倒**，正好是规格 §4.2 明令禁止的那条。
所以个位固定 0，副标写明 `ROUNDED TO 10`；4.2 亿的量级上这点误差可忽略。

十位轮（4.8 格/秒）**整格跳**不做插值 —— 连续滚会让它永远停在两个字之间，
暂停时更是直接冻在半个字上，像渲染坏了。百位及以上走机械齿轮，只在低位走完最后 4% 时翻。

后 3 位缩到 60% 字号：这一段一直在动，大字号下的滚动残影会糊掉整个数字的可读性。
「大整数 + 小尾数」本来就是交易所报价屏的做法。

### 3.3 大额单没有把金额字号做大

原始要求是「金额字号略大」。**做不到，因为会破坏字符格对齐** —— 格宽由字号决定，
单独放大金额那 10 格会让它们逐格外溢、和其他行错位。而对齐精度是这个方案高级感的全部来源。

替代的强调手段（实测足够抢眼）：`--accent` 色 + 加粗 + `--panel` 底色带 +
左侧 2px accent 色条 + 行首 `*` 放大到 1.4em + 翻页更慢（26ms stagger / 5~7 次翻）+
**顶部多停 1.9 秒**再被下一单推下去。

### 3.4 其它

- **千分位用 0.18em 细间隙而不是逗号**：出版物 / ISO 31-0 做法，比逗号干净，也省 1 位宽度。
- **32:9 目前留黑边**（规格 §5 允许）。弹性切栏没做，见待办。
- **`--mute` 级文字对比度约 4:1**（`#7A7166` on `#12100E`）。用在页脚免责、
  仪表标签、副标这类「走近看」的第三层信息上。表格列头已经提到 `--sub`（约 8.7:1）。
  `--text` 主文字 16.6:1，达标。
- **表格字号 26px（字高约 17px）**，设计给 1~3 米走近看。5~10 米的阅读交给巨型数字
  和里程碑大字。这是「报价板」这个参照系的固有性质 —— 机场航班牌也是走近了才读细节。
- **CJK 商品名字距略松**：全角字占 2 格，而回退 CJK 字体的实际字宽约 1.8 格，
  所以每字右侧有约 0.2 格空隙。换来的是列位零漂移。
- **里程碑齐翻只响一次 `blip()`**，不是 10 次 —— 10 行同时起翻，10 次 blip 会叠成一声爆音。
- **磁带预填**：开屏不能是空表。用 `peekOrders(48)` 里最远的 10 单改写时间戳当「刚刚过去」。
  它们约 40~60 分钟后才真正到达，而 10 行磁带周转约 9.5 分钟 —— 到时候早滚出屏幕了，
  不会出现重复行。预填行直接落位，不翻页、不发声。
- **`R` 重置会重新预填磁带**，不会留一张空表等 10 分钟；预填与重置的行位是「无过渡」
  就位的（那一屏本来就已经在那儿了，不该看到十行依次滑动）。
- **开幕时刻兜底**：`T0` 是硬编码的 2026-08-18 09:00 (UTC+8)。如果机器时间还没到
  `T0 + 1h`，三个数字全是 0、磁带也空。这时把虚拟时钟推到 `T0 + 4h`（日内上午高峰），
  画面立刻是「开着的」。彩排 / 异地演示必然踩到这条。

## 4. 上会前待办

1. **人声必须换成离线合成的音频文件**（规格 §3 红线）。现在靠浏览器
   `speechSynthesis` 顶着，展会机上中文音色可能不存在或依赖联网。
   代码已经在读 `APAudio.voiceAvailable`，调试网格里显示 `VOICE OK / NA`。
2. **量级请产品确认**：`PAGES0 = 6,144,000`、`CRAWLS0 = 420,000,000`、
   `ORDERS0 = 296,000` 都是引擎里的对外口径，不得超过公司最大公开口径 × 1.2。
   屏上磁带右侧走的是 `metrics().session.orders`（**开幕至今**，`THIS SHOW nnn ORDERS`），
   刻意不用 `metrics().orders` 那个 29.6 万起步的全量累计口径 —— 后者写在屏上必被问成
   「今天卖了 29 万单？」。巨型数字仍是全量累计的 `crawls`（4.2 亿），那个量级是加分项。
3. **上真 LED 屏后按 `G` 看一遍**：确认巨型数字和金额列没压在拼缝上；
   确认 hairline 和 `--mute` 文字在展厅顶光下还看得见（看不见就整体提一档）。
4. **`APAudio.selfTest()` 开机自检**：HDMI 会把默认音频输出切到显示器，现场必测。
   建议在遮罩上加一个「音频自检」小按钮，现在只在 console 可调。
5. **展馆模式**：现场大概率要常开 `H`（切 100Hz 以下 + 补人声频段）。笔记本预览保持关。
6. **店名碰撞检查**：虚构名来自引擎，上会前再过一遍是否撞到真实 DTC 品牌。
7. **32:9 / 21:9 弹性切栏**：现在留黑边。要填满的话把仪表列拆成第三栏，
   `TAPE_W` / `HERO_W` 改成运行时算（字符格网格本来就是量出来的，改动可控）。
8. **FPS 自动软重置**：现在只在 60 帧均值掉到 40 以下时 console 告警（每 30 秒最多一次）。
   正式版需要连续低帧时自动 reload。
9. **`?debug=grid` 的基线网格用了 `repeating-linear-gradient`** —— 只在调试层，
   启动时建一次，不在 rAF 里。生产画面零渐变。
