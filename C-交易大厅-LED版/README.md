# 方案 C-LED「交易大厅」· 点阵报价墙

> **AI 引荐订单 · 实时成交板**

`C-交易大厅` 的**平行版本**，不是替代。原版是暖墨陶土 + split-flap 长表（出版物气质），
这一版照真实券商报价墙做：纯黑 + 点阵 LED + 成交带 + 市场墙。两版都留着对照。

参考图在 `../../参考-交易大厅/`，主要依据 `03-东京电子报价板.jpg`。

---

## 1. 报价 ≠ 成交（这一版最重要的一处修正）

第一版把「订单」做成了「报价」：一个格子里的数字换一下。但真实交易大厅里这是两件事：

| | 是什么 | 观感 |
|---|---|---|
| **报价** | 持续跳动的价格 | 环境噪音，跳一下不代表任何事发生 |
| **成交** | 真正的交易 | ticker tape 里 tape 印的就是成交；大单打出来交易员要喊 |

AP 订单本质是**成交**。所以第一版看起来"什么都没发生"—— 那一格跟旁边 17 个数字长得一模一样。
现在分成两层：

### A 层 · 报价墙（环境）

**18 个格子 = 18 个市场**，每格显示该市场今日累计 AI 引荐成交额（只涨不跌）+ 笔数。
每笔成交必然落在某一格 → 墙永远是活的。这才是真正的「报价」。

> **为什么是市场而不是店铺**：一格一店的话，464 家店只有 18 家在墙上，
> 96% 的成交点不亮任何格子，墙就是死的。一格一市场则每笔成交必然命中，
> 而且「按市场看成交额」本身就是有用的信息。
> 格子里的金额统一用**美元** —— 一墙 18 个市场要能互相比较，混着币种没法比。

### B 层 · 成交带（事件）

**逐笔成交打印**，从右侧推入，每行：
```
11:13:59   BAFI   Basin Field        US    USD 241.45   GPT   ▬▬▬▬▬▬▬▬▬▬▬▬
```
最右侧是**成交量条**（长度 ∝ 金额，对数刻度）—— 一眼比出这一笔多大，
这是报价板上最省事也最有效的量级表达。金额用**本地币种**，地域感在这一层。

### 双主角

| | 指标 | 分工 |
|---|---|---|
| 左 | AI 爬虫累计访问 | 40/秒，负责「一直在动」 |
| 右 | **AI 引荐累计成交额** | 一分钟跳一次，但它讲的是「**钱进来了**」 |

成交时右上浮出 `+$278.53` 并上浮消失；成交额数字是**滚上去**的（260ms 缓动追目标），
不是硬跳 —— 这一下滚动就是「进账」的感觉。

### 大额仪式

- `epic`（≥$300）：成交行**全宽高亮 + 红字**，成交量条变红
- `legendary`（≥$792）：成交带位置压出一条 **3.4 秒横幅**，巨型红色金额 + 店名 + 来源
- 人声播报由 `APAudio` 按稀有度自动决定（`rare` 及以上才播，约每 2.4 分钟一次）

## 2. 让人认出「交易大厅」的是未点亮的灯珠

身份信号有两层：字形由可见灯珠组成，**以及没点亮的灯珠也看得见**，形成一片暗的网格底纹。
第二层比第一层更关键 —— 只画亮点会像低分辨率字体，加上底纹才有「一块真实 LED 板」的实体感。

实现上没有手工点阵字库（36 个拉丁字形起步，而且商品名有德语/日语/西语，中文根本没法手工做）。
改成**把文本按「1 像素 = 1 颗灯珠」画到离屏 canvas，再逐像素采样**决定哪颗亮。
任意字形任意语言通吃，零字库维护。见 `led.js`。

灯珠填充率约 **63%** —— 真实 LED 的珠子更小、缝更大，亮点才离散清晰。
（第一版给到 73%，字看起来会糊。）

---

## 3. 整墙不能按年龄压暗（第二版另一处修正）

第一版用亮度编码新旧：新单最亮，越老越暗，量化成 5 档。结果**整墙发灰** ——
订单一分钟才一笔，24 格里任何时刻都有 22 格处在暗档（金额色是 `#4A330A` 这种深棕）。

真实报价墙**每一格永远是满亮度**，这是 LED 墙的全部意义。回看东京那张照片，
每一个价格都是全亮的红，没有任何一格是暗的。「刚跳动」靠那一格在闪来表达，不靠把别人调暗。

现在：所有格子的字一律满亮度；新鲜度用**外框**表达 ——
520ms 内白框脉冲两下，之后 9 秒琥珀框渐隐。

## 4. 配色按「字段」分工，不按「涨跌」分工

| 字段 | 颜色 |
|---|---|
| 国家码 / 店铺代码 | 白 `#F2F2F2` |
| 金额 | 琥珀 `#FFB020` |
| 笔数 / 币种码 / 来源码 | 绿 `#35D06A` |
| 大额成交 | 红 `#FF3B30` |

真实报价墙也是按字段上色的（东京板：名称白、价格红；菲律宾板：代码绿、价格琥珀）。
更重要的是这样能**绕开「红涨绿跌」的语义争议** —— 国内红涨绿跌、欧美相反，
而我们根本没有「涨跌」这个概念，用字段分工就不会被误读。

**这一条仍需要跟业务同事确认**：如果他们希望用红绿表示金额档位，得先明确给谁看 ——
国内商家看到红色会本能理解成「涨」。

---

## 5. split-flap 只留给里程碑

真实报价墙是灯珠直接闪变换色，**没有翻页**；机械翻页是机场航班牌的语言，混用会四不像。

- **常规更新** = 点阵闪变（白框脉冲两下，520ms）
- **里程碑** = **全屏齐翻**：18 个市场格的国家码、金额、笔数、市场名全部乱翻，
  按列 90ms 递延形成从左到右扫过的一波，每 70ms 换一次乱码（机械翻页的节奏），
  同时中间浮出巨型 LED 里程碑数字。乱码只在同类字符里换（数字换数字、字母换字母）。

里程碑约 30 分钟一次（抓取量 / 订单数跨阈值）。**页面里程碑不触发全屏**
（约 14 分钟一次，太频繁，只给一声轻提示）。演示时按 `K` 手动触发。

## 6. 版面

垂直节奏是**倒着算**出来的：公开数据铭牌固定在 936，报价墙 3 行 402px 必须收在 924，
所以墙从 522 起 → 成交带 396..504 → 仪表条 338..382 → 双主角副行 322。

| 区域 | y | 内容 |
|---|---|---|
| 机身丝印 | 38–88 | 品牌 + 一句话 + 时钟 + 模拟数据角标（**清晰字不做点阵** —— 真实机器的丝印就是印上去的；合规角标更不能做成点阵） |
| 跑马灯 | 96–148 | 真实爬虫日志滚动（真 UA 名 + 真 ASN + 真数据中心 + 真多语言路径），82px/s |
| 双主角 | 176–322 | 左：爬虫累计访问　右：AI 引荐累计成交额（灯珠间距 8，圆点） |
| 仪表条 | 338–382 | 5 列：抓取速率 / AP 页面 / 今日订单 / 订单节奏 / 平台占比 |
| **成交带** | 396–504 | 3 行成交打印 + 成交量条 |
| **市场墙** | 522–924 | 6 列 × 3 行 = 18 个市场，每格 296×130 |
| 公开数据铭牌 | 936–998 | Adobe 66% / 1.42× / Shopify 13×，浅底金属铭牌质感 |
| 页脚 | 1014 | 模拟数据声明 + 商标声明 |

**开场铺满**：把「本场至今」的成交额与笔数按市场权重摊到 18 格（带 ±18% 确定性抖动，
避免看起来像等比例分配）。这样铺出来的数跟引擎的 `session` 口径是一致的，
而且首帧不是空板 —— 空板在展会上是硬伤。

## 7. 性能

| 手法 | 效果 |
|---|---|
| 18 个市场格各自缓存到离屏 canvas | 只在内容变化时重绘（订单约 1 分钟一笔） |
| 成交打印行渲染一次成精灵图 | 推入动画只是改 drawImage 的 x |
| 巨型数字按 (字形, 颜色) 缓存精灵图 | 每帧只有十几次 drawImage，而不是几百次灯珠路径 |
| 跑马灯每段缓存精灵图 | 滚动只是改 x |
| 未点亮底纹预先烘成画布 | 不用 CanvasPattern（pattern 跨 context 使用属实现相关行为），也更快 |
| `imageSmoothingEnabled = false` | 灯珠是硬边的，不要插值 |

实测（headless、1920×1080）：**DOM 节点恒定 100**、无 console 报错、计数器持续递增、
`file://` 双击可跑。`window.APDiag` 有实时 fps / 60 秒均值 / 精灵图缓存条数；
均值掉到 40 以下打一次 console 警告。

**帧率没有在展会机上量过** —— headless 不按 60Hz 驱动 rAF。上会前必须真机跑一次。

## 8. 快捷键

与其他方案完全一致：`空格` 暂停　`B` 人工大单　`N` 普通单　`K` 里程碑齐翻
`M` 静音　`A` 环境音床　`H` 展馆音频　`1/2/3` 速率　`G` 调试网格　`F` 全屏　`R` 重置　`?` 图例。
另有 `?hero=session` 把左主角切成「本场新增」口径。

> `B` / `N` 只把订单**入队**，不直接处理 —— `triggerOrder` 会进引擎队列，
> 下一帧 `pollOrders` 还会返回同一笔。第一版在按键里直接处理，导致一笔单
> 打印两遍、音也响两遍（截图里出现过两行完全相同的成交）。

## 9. 已知取舍

1. **市场墙的金额是美元，成交带的金额是本地币种。** 前者要能横向比较，后者要地域感。
   两者口径不同，屏上分别标注了「（美元）」和币种码。
2. **店铺代码是 4 字母**（`Cove Wharf` → `COWH`）。格子放不下长店名（296px 在灯珠间距 3 下
   只有约 90 颗灯位），而真实报价墙本来就用代码。**店全名在成交带里有**。
3. **成交带只有 3 行**，也就是只看得到最近 3 笔。再多就要挤掉市场墙的一行。
   如果希望看到更长的成交历史，可以把市场墙压成 2 行、成交带加到 6 行 —— 需要你定。
4. **金额去掉了货币符号**，币种改用旁边的三字母码。`MX$10,320.00` 是 12 字符 300px 必然溢出；
   裸数字只要 150px。真实报价墙的价格栏也是裸数字。四位数以上不显示小数。
5. 超宽屏（21:9 / 32:9）是等比缩放 + 左右留黑。这个版面天生适合超宽 —— 市场墙加列就行。

## 10. 上会前待办

1. **人声换成预先离线合成的音频文件**（现在靠浏览器 `speechSynthesis` 顶着，
   展会机上中文音色可能不存在或依赖联网）。不做的话现场大概率是哑的。
2. **在真机上量一次真实帧率**，跑 30 分钟看 `APDiag.fpsAvg`。
3. **跟业务同事确认红/绿语义**（见第 4 节）。
4. **确认观看距离**：市场墙第三行的市场名和币种码约 24px 高，5 米外读不到。
   如果观看距离普遍偏远，把市场墙改成 5 列 × 3 行（格子宽 +60px）可以再放大一档。
5. 确认 `CONFIG` 里三个对外口径（页面存量 / 累计抓取 / 累计订单 + GMV 基线）。
6. 到场必查：HDMI 插拔会把系统默认音频输出切到显示器（显示器没喇叭 = 全场静音）。

# 第三版改动（2026-08-19）· 清晰、简洁、成交流当主角

第二版把「报价」和「成交」分开了，方向对，但**太密、层级不清、市场格看不清**。
这一版做了三件**减法**，上文与本节冲突的地方以本节和代码为准。

## 1. 删掉整条仪表区

原来 5 个指标（抓取速率 / AP 页面 / 今日订单 / 订单节奏 / 平台占比）占了一整条横条。
现在折进两个主数字下面的副行：

```
AI 引荐累计成交额  CUMULATIVE AI-REFERRED GMV        AI 爬虫累计访问  CUMULATIVE AI CRAWLS
$41,390,440                                                        424,033,706
今日 +$246,440 · 1,755 笔 · 平均每 57 秒一笔        34.7 次/秒 · 6,249,268 个 AP 页面已被 AI 收录
```
平台占比收成「成交流」标题右侧的一行小字（带色块）。**少一层横条，密度立刻降下来。**

## 2. 市场墙 18 格 → 6 格

5 个主要市场（US / GB / DE / FR / CA）+ 第 6 格 **OTH 聚合**（其他 13 个市场）。

> **为什么必须有聚合桶**：只放 5 个市场的话，剩下 13 个市场的成交点不亮任何格子，
> 墙会时不时僵住。有了聚合桶，每一笔成交必定命中某一格，
> 而且 **6 格相加 = 主数字的成交额，账是平的**。

格子从 296×130 变成 296×96 但只有一行，视觉上大得多也清楚得多。
市场名从格子里挪到区块标题右侧当图例（`US 美国　GB 英国　…`），格子里只留代码 + 笔数 + 金额。

## 3. 成交流 3 行 → 9 行，并加表头

**「分不清谁是谁」最直接的解法就是给表加表头**：

```
时间 TIME    代码 CODE   店铺 STORE          市场 MKT  币种 CUR   金额 AMOUNT   来源 SOURCE   规模 SIZE
12:46:32     LELA        Lesser Lab          AU        AUD          542.18     GPT           ▬▬▬▬▬▬▬▬
```
加了斑马底（相邻行交替深浅），长表格里最省事的可扫读手段。
最新一行左侧标记条加亮 + 一道 10% 横向高光，明确「这条是刚进来的」。

## 4. 两个主数字左右换位

**成交额放左边**（第一阅读位，白色标题），爬虫数退到右边（灰色标题 + 稍暗的琥珀）。
用**位置和明度**表达「成交是主角」，而不是靠字号打架。

## 5. 列位是按最坏情况算出来的，不是估的

第二版这里有个真 bug：时间列和代码列重叠，屏上显示成 `12:45:11HAFO`。

- 时间 `12:45:11` 是 8 个字符 × 10 灯 × 间距 2.2 = **176px** → 代码列必须 ≥ 200，原来放在 178
- 店铺名截断到 **20 字符**，约 400px → 市场列必须 ≥ 332 + 400 = 732

现在列位：`时间 16 / 代码 212 / 店铺 332 / 市场 800 / 币种 892 / 金额右对齐 1150 / 来源 1196 / 规模条 1330`。

## 8. 去掉公开数据铭牌（2026-08-19）

按要求移除屏幕下缘的「公开数据 PUBLIC · 66% / 1.42× / 13×」整块铭牌
（`index.html` 的 `#pub` 与其 CSS 一并删除）。腾出的空间还给内容：

- **成交流 9 行 → 10 行**（364..824）
- **市场格加高** 96 → 100，位置下移到 862..962
- 页脚上移到 988

**合规元素没动**：右上角 `模拟演示数据 · SIMULATED` 角标、页脚的
「本屏数据为产品能力演示，非真实交易记录」+ 商标声明，都还在，任何一帧截图都带得上。

> 一个提醒：屏上现在**没有任何真实可核实的数据**了，全是模拟值。
> 如果 BD 现场需要外部论据（Adobe 的 66%、Shopify 的 13×），
> 建议做成屏幕旁边的一块静态展板 —— 那样既不占屏，也不会有
> 「真数据给假数字背书」的视觉混淆问题。

## 9. 去掉「模拟演示数据 · SIMULATED」角标（2026-08-19）

按要求移除右上角的角标（`index.html` 的 `#badge` 与其 CSS）。时钟原来是为了避开它
才放在 `right:470px`，现在挪到右边缘 `right:56px`。

**保留的声明**：页脚仍有「本屏数据为产品能力演示，非真实交易记录。OpenAI、ChatGPT…
均为其各自所有者的商标；AP 与上述公司无隶属、赞助或合作关系。」
启动遮罩上也仍有「本屏数据为模拟演示数据」。

> ⚠️ **残留风险要记在这里**：调研结论是「免责必须醒目、且与数据相邻，不能只藏在角落小字」
> （参照金融业对 hypothetical / backtested 业绩的披露做法）。角标去掉后，屏上的声明
> 只剩页脚那一行小字。风险场景是**截图与录屏外传** —— 画面里 $41,392,163 的成交额
> 看起来像真实业绩，而页脚小字在压缩后的截图里往往看不清。
>
> 如果之后想补回一层而又不想要那个醒目的方框，可选的轻量做法：
> 把「模拟演示数据」并进页脚那一行的**开头**（不新增元素、不占版面），
> 或者只在**里程碑全屏庆祝**那几秒叠一次。这两种都不影响常态观感。
