# 方案 A · 任务控制台 (Task Console)

> AI 时代电商的任务控制台。参照系是 Datadog / Grafana 的 NOC 墙、发射直播的叠加层、
> 彭博终端 —— **科技感来自真实数据密度，不来自特效**。
> 全屏没有一处渐变、发光、扫描线、粒子、切角边框。

打开方式：双击 `index.html`（`file://` 直接跑），或用上级目录的 `启动预览.bat`。
文件：`index.html`（结构 + 全部样式）、`app.js`（全部逻辑，classic script）。

---

## 1. 设计意图

**一句话**：把「AI 正在读你的商品页」这件抽象的事，变成一屏可以逐行读的证据。

### 灵魂在右边那一栏
右侧 38% 是一条 8 条/秒向上滚动的 HTTP 访问日志，等宽字体、列对齐：

```
19:53:41.052  OAI-SearchBot   20.49.x.x   Microsoft Azure  /products/organic-cera…  200  40.5kB  235ms
19:53:52.302  PerplexityBot   20.171.x.x  Microsoft Azure  /products/merino-cotto…  200  39.9kB  289ms
19:54:11.052  GPTBot          44.221.x.x  Amazon AWS       /collections/schwer-ca…  200  12.6kB  226ms
```

这一栏是全屏最"贵"的地方。懂行的观众看一眼真实 UA 名（`GPTBot` / `OAI-SearchBot` /
`ClaudeBot` / `Google-Extended` / `PerplexityBot`）和真实出口 ASN（`Microsoft Azure` /
`Amazon AWS` / `Google Cloud` / `Cloudflare`）就知道我们真在做这件事 —— 这是最便宜也最
不可伪造的可信度。**只给 bot 名上色**，五个平台用同一支青绿家族里极轻微的色差区分，
其余全部走 `--sub` / `--mute` 灰阶，所以整栏读起来是"纹理 + 一列高亮"，不是彩虹。

### 左边 62% 是三层结论
| 层 | 内容 | 视觉重量 |
|---|---|---|
| 主角 | AI 爬虫累计访问次数（`metrics.crawls`），机械里程表巨型数字，`--crawl` 青绿 | 唯一的饱和色 + 唯一在持续运动的大字 |
| 配角 1 | AP 翻译页面总数 + 到下一个里程碑的进度条（"距 6,196,000 还差 680"） | 主角的 ~18% 字号 |
| 配角 2 | 平台占比堆叠条（与线上 Platform Breakdown 同口径） | 12px 高的一条 |
| 换算行 | `≈ 每 57 秒 一笔 AI 引荐订单` / `≈ 每分钟 65 个新 AP 页面` | 解决"大数字没有参照系" |
| 事件区 | 订单卡，最多 4 张可见，靠动效抓眼不靠尺寸 | 屏高 ~16% |

**为什么强调"还差多少"**：人对缺口的注意力远高于存量。进度条每约 15 分钟走满一次，
所以它是全屏第二个"会完成"的东西 —— 观众会等它。

### 背景是一张 2D 世界点阵地图
遍历 `APGeo.CITIES`，等距圆柱投影 `x=(lon+180)/360, y=(90-lat)/180`，`--mute` 色、
alpha 0.16~0.36；再用 `APEngine.hash32` 给每座城市生成确定性的卫星点堆出人口带，
大陆轮廓就自然浮现，不需要任何地图数据文件。每来一条抓取，对应数据中心的点亮
300ms 后按 `(1-t)²` 衰减。经纬线走 `--grid` opacity .06。
**克制到几乎是纹理** —— 3D 地球是方案 B 的活儿，两个方案一眼能分开。

### 公开数据与模拟数字硬分区
页脚左侧是**浅底卡片**（`#E9EBEE` 底 + 深色字），每 12 秒换一张，带来源域名小字；
模拟数字全部在深底上。真数据绝不给假数字背书，这条在视觉上就断开了。

## 2. 五个自建部件

| 部件 | 做什么 | 怎么满足红线 |
|---|---|---|
| `Odo` | 机械里程表 | 每位一个 `width:1ch;overflow:hidden` 槽，整体 `flex-end`；槽里是 `0..9,0` 字条，改数字 = 改 `translate3d`，**从不改 textContent**；齿轮式进位 + `smoothstep`（终点导数 0，无 overshoot） |
| `Log` | 日志流 | 30 个固定 DOM 行循环复用，只写 textContent + transform，**永不 append/remove**；整列位置 = 底部锚点 − (连续行号 − 本行行号) × 行高，临界阻尼趋近 |
| `Map` | 点阵地图 | 静态点阵 + 经纬线启动时烘到离屏 canvas，rAF 里只 `drawImage` + 画衰减点；**绝不在 rAF 里 createLinearGradient/createPattern** |
| `Deck` | 订单卡 | 10 个 DOM 对象池，最多 4 张可见；入场 480ms `easeOut` + 8px 位移，退场 240ms 慢进快退；`will-change` 只在动画期间挂、settle 后在帧循环里摘掉（不靠 setTimeout） |
| `Cel` | 里程碑庆祝 | 4.2 秒全屏（400ms 入 / 3200ms 持 / 600ms 出）+ `APAudio.playMilestone()`；90 秒冷却做安全阀 |

其他：随机全部走 `APEngine.hash32`（**零 `Math.random`**，彩排可复现）；动画步长全部走
`APEngine.dt()`；巨型数字字号由 JS 用 canvas/DOM 实测字宽后写入 `--hero`，字体回退到
Segoe UI 也不会溢出到日志栏；主循环包一层 `try`，单帧异常不会让整块屏死掉，
异常留痕在调试网格里（`err N [message]`）。

## 3. 快捷键

| 键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续（左上 `LIVE` 变 `PAUSED`） |
| `B` | **人工触发一个大单**（BD 讲到关键处的那个键） |
| `N` | 触发一个普通单 |
| `K` | 触发里程碑庆祝 |
| `M` | 静音 / 取消静音 |
| `1` `2` `3` | 速率 ×0.5 / ×1 / ×3（`LIVE ×3` 会显示出来） |
| `G` | 调试网格 |
| `H` | 展馆音频模式（切 100Hz 以下 + 补 2~4kHz） |
| `A` | 环境音床 |
| `F` | 全屏 |
| `R` | 重置 |
| `?` | 快捷键图例 |

URL 开关：
- `?debug=grid` —— 调试网格（12 列 / 8px 基线 / **青绿虚线 = 规格 6% 安全区** /
  **暖金实线 = 实际内容框** / 中线），并在左上角实时显示
  `stage / scale / hero px 与 cap 占屏高比 / 日志行数×行高 / path 列宽 / fps / DOM 节点数 / 语音可用性 / 异常数`。
- `?log=NN` —— 日志栏宽度百分比（26~46，默认 38）。这是本方案唯一的
  「主角字号 ↔ 日志可读性」旋钮，见下面取舍 1。

启动遮罩点击时执行 `APAudio.unlock()` + `setVoiceLang('zh-CN')` + `selfTest()`
（现场开机自检：HDMI 经常把默认输出切到显示器，两声铃就能确认音频链路是通的）。

## 4. 已知取舍（这一节请当验收清单读）

**1. 主角 cap height 只有屏高 ~16%，不是规格 §4.3 的 30~50%。这是几何硬限制，不是偷懒。**
`metrics.crawls` 带 `CRAWLS0 = 420,000,000` 的历史基数，展会全程稳定在 **9 位数**
（第 0 天 4.20 亿 → 第 30 天 5.54 亿，不换位数，所以永远不重排版）。
9 位数 + 2 个千分位逗号，在左栏 990px 净宽里，实测字号上限 248px → cap ≈ 176px ≈ **屏高 16%**。
要做到 32%（cap 345px）需要约 **1,730px 净宽**，等于整屏放弃日志栏 —— 而日志栏是这个方案
的灵魂。**选择保留日志栏**，用「唯一饱和色 + 唯一持续运动 + 四周留白」维持主角地位，
而不是靠尺寸。想在现场对比，按 `?log=30` 能换回约 8% 的字号。

**2. 个位数字是连续旋转的一片模糊，这是故意的。**
抓取真实速率 47.6 次/秒，比帧率还快 —— 个位一秒转 4.8 圈，任何实现都只能是模糊。
它不是"每帧假随机跳动"（规格禁止的那种），它携带**速率**这个信息，读起来像加油机或
盖格计数器。十位及以上走齿轮式吸附：只在低位走完最后 10% 时才转。
离线实测：**90.6% 的帧里高位是整数像素对齐的**，单调性违例 0（wrap 除外）。

**3. 全屏中文文案约 76 字，超过规格 §4.5 的 ≤25 字。**
NOC 风必须给每一栏一个标签，任务书也明确允许 A 的信息密度更高。已经删掉能删的
（原来的「日志采样 8」和主角右侧的「次 / visits」都删了，后者顺便把宽度让给了数字）。
如果验收要求硬压到 25 字，可删的候选：换算行第二条、「平台占比」的中文标签、
「AI 爬虫抓取日志」的中文副标题。

**4. 外框边距 80px（4.2%），小于规格的 6%（115px）。**
NOC 密度需要这 70px。调试网格**同时**画 6% 安全区和实际内容框，到场 30 秒就能确认
巨型数字有没有越过安全区。如果现场 LED 有物理边框吃边，把 `S.pad` 的 `0.0417` 改成
`0.06` 即可，自适应会自动把字号缩下来。

**5. 订单区刻意不显示"全站累计订单"，只显示「开幕以来 N 单 · $X」。**
引擎里 `metrics().orders` 带 `ORDERS0 = 296,000` 的 7 个月历史基数，而 `metrics().gmv`
**没有**基数、从开幕 T0 起算 —— 这两个数配在一起被人一除就是 AOV $0.30，一眼假。
所以用同一条积分的 `metrics().session.orders` / `.session.gmv`：AOV 约 $139，算得通；
而且 T0 是硬编码锚点，断电重启也不会归零（不违反"计数器不倒退"）。
代价是屏上少了一个 29 万的大数字 —— 换来的是"任何人拿计算器都算不穿"。
代码里对 `m.session` 做了存在性兜底，共享库万一回滚也不会白屏。

**6. 地图是"暗示"级别，不是精确海岸线。**
120 座城市 + hash32 生成的确定性卫星点。北美东西岸、西欧、东亚、南亚、澳洲能认出来；
非洲内陆和南美内陆是空的（数据里没有城市）。因为它只是极暗的背景纹理，这不影响读图。

**7. Canvas 内部分辨率 = 左栏的设计像素尺寸（约 990×872），不是 1920×1080。**
它只占左栏，按 1920×1080 会横向拉伸变形。规格 §2.6 的意图是「锁设计分辨率、不乘
devicePixelRatio」，这里完全遵守（4K 屏上它就是半分辨率纹理，2 米外看不出）。

**8. 人声用浏览器 `speechSynthesis` 顶着。** 见待办 1。

**9. 里程碑约每 8.6 分钟一次全屏 4.2 秒**（页面每 1,000 页 ≈ 15 分钟、订单每 50 单
≈ 38 分钟、抓取每 25 万次 ≈ 87 分钟，实测合计 7 次/小时）。这期间日志栏被盖住。
节奏上是好的，但如果 BD 反馈打断讲解，把 `Cel` 换成右上角横幅样式即可（逻辑不用动）。

**10. 超宽屏是弹性切栏，不是纯留黑边。** stage 宽度在 1920~2560 之间跟着画面比例伸缩
（`--stage-w`），日志栏按 38% 跟着长，巨型数字重新实测字号；超过 2560 才留黑边。
实测 1280×720 / 1920×1080 / 3840×1080 布局都不炸。

**11. FPS 自监控只打 console 警告，没有自动软重置。** 见待办 6。

## 5. 上会前待办

1. **人声必须换成预先离线合成的音频文件**（Azure / ElevenLabs 一次性生成整句，免费额度内）。
   浏览器 TTS 的中文音色在展会机上可能根本不存在，或者依赖联网 —— 断网就哑。
   代码里已经有降级：`APAudio.voiceAvailable === false` 时只出音效并打 console 警告，
   调试网格显示 `voice MISSING`。
2. **在真实 LED 墙上跑一次 `?debug=grid`**，确认巨型数字和进度条没有压在拼缝上；
   同时用 `?log=32 / 34 / 38` 现场比一次，定最终宽度比（这是全屏最大的一个可调项）。
3. **三个量级口径要产品签字**：`PAGES0 = 6,144,000`、`CRAWLS0 = 420,000,000`、
   `ORDERS0 = 296,000`。引擎注释里写了「不得超过公司对外最大公开口径 × 1.2」，
   这一条得有人负责。
4. **虚构店铺名再过一遍碰撞检查**（引擎注释也提到了）。屏上会出现 `Aster`、`Pine Mill`
   这类名字，确认没有撞到真实 DTC 品牌。
5. **确认展会机装了 Bahnschrift**（Win10/11 自带）。如果播控机是 macOS / Linux，
   `--font-hero` 会回退到 Segoe UI / system-ui，自适应保证不溢出，但 cap 会更小；
   那种情况建议改用当地系统里的窄体无衬线。
6. **长跑加固**：FPS 掉到 40 以下自动软重置（现在只打 console 警告）；
   断电自启（Windows 计划任务 + Chrome kiosk + `--autoplay-policy=no-user-gesture-required`，
   注意后者会让启动遮罩失去解锁音频的必要性，但遮罩本身还是要留着做合规声明）。
7. **音频现场流程**：开机 → 点遮罩（自动自检两声铃）→ 按 `H` 开展馆模式 → 按 `A` 决定
   要不要环境音床。展馆 85dB 上限，人声门槛已经是 `rare`（约每 2 分钟一次），别调到 `common`。
8. **公开数据三条要复核**发布时间与原文口径；页脚商标声明请法务过一遍。
9. **合规复查点**：全屏无第三方 logo，无「GPT 订单」字样（一律「AI 引荐订单 /
   AI-referred order」）；`模拟演示数据 · SIMULATED DEMO DATA` 角标常驻在顶栏右侧，
   字高 24px，任何一帧截图都带得上；页脚商标声明常驻。

## 主 agent 复核后的改动（2026-08-18）

交付后我用 Playwright 在 1920×1080 真跑截图复核，改了四处。这几处与上文中
"设计意图" 章节的部分表述相冲突，**以本节为准**。

1. **个位数字由「连续旋转」改为「整格吸附」**（`Odo.prototype.set`）。
   原设计让个位连续转出模糊感（加油机效果），动起来确实好，但两个实测问题：
   ① 每秒 48 格、60Hz 下每帧走 0.8 格，会产生走马灯式的**视觉倒转**，正好是
   规格 §4.2 明令禁止的"数字倒退"，且这不是缓动问题、改缓动无效；
   ② 媒体拍照和录屏会定格在半个字形上，看起来像渲染坏了 —— 截图已复现。
   整格跳变仍然每帧都在变，"快"的感觉不丢。

2. **新增「最新一笔」大卡** `.ohero`（`Hero` 对象）。原实现所有订单都是 36px 细行，
   稀有度差异只有 22→24→26px 字号，`$266` 和 `$3` 看起来一样重，拿不到老板要的
   "到账"情绪。现在最新一笔占一张 140px 大卡，金额 64 / 76 / 84px 三档分级，
   epic 及以上额外走一次底部横线扫过（一次性、承载稀有度信息，不是循环装饰）。
   顺带用掉了订单区下方原本约 25% 屏幕的死空间。
   `ORD_VIS` 由 4 改为 3，`.ord-pool` 高度 168→120px 给大卡腾位置。

3. **历史列表改为显示"被顶下来的那一笔"**，而不是当前这一笔 —— 否则大卡和列表
   第一行是同一单，看起来像重复渲染。

4. **共享引擎的 `fmtMoney` 改为一律用 `en-US` 排版**（这条改在 `_shared/engine.js`，
   四个方案共同受益）。原因：CAD / AUD / SGD / MXN 在各自 locale 下都渲染成裸 `$`，
   屏上出现的 `$16,338.80` 其实是墨西哥比索（约 950 美元），观众会读成 1.6 万美元
   —— 这等于把我们自己的数字夸大 17 倍。现在渲染成 `MX$` / `CA$` / `A$` / `SGD`，一眼可辨。

另外确认 README 上文关于 **主数字 cap height 只有 16%** 的分析是对的，但结论要改：
共享规格里"cap height 达到屏高 30~50%"这条要求本身写错了。10 位数字 + 2 个逗号在
16:9 上几何上限就是 17~20%，双十一那种大屏本身也是 11 位数、cap height 约 15~20%
—— **冲击力来自宽度铺满 + 持续运动，不是字高**。规格 §4.3 已按此修订，本方案不需要改。
