# 方案 E · 实时看板（V1 版式 · 展会商家口径）

> **平行版本。** 与 `E-运营监控台` 并存，A/B/C/D 与 C-LED 两版也原样不动。
> 打开：`http://localhost:8099/E-监控台-V1版式/index.html`，或双击 `index.html`。
> 换主题：**按 `T`**（屏上没有入口，只有操作员知道）。

## 这一版的定位

版面严格照 V1 静态稿，但**文案与信息口径全部按「展会上给商家看」重写过**。
判据只有一条：**屏上每一个字，一个国内 DTC 商家都得看得懂**。

`顶栏 56 │ 远距离层 168 │ 中段 464 │ 下段 392 = 1080`。页脚整条省掉，腾出的 44px 给中段。

## 改名对照（这一轮的核心）

| 原来（内部口径） | 现在（商家口径） | 为什么 |
|---|---|---|
| 运营监控台 | **实时看板** | 「运营监控台」是我们内部的说法 |
| AI 引荐累计成交额 | **Agentic Page 带来的成交额** | 「引荐」商家看不懂。曾经叫「AI 助手带来的」，但那把功劳归给了 AI 助手 —— 助手只是渠道，让商品页能被读懂、把顾客带进店的是 Agentic Page。归因给自己的产品，顺带也更远离「暗示与 OpenAI 有合作」那条红线 |
| 爬虫抓取速率 · 次/秒 | **AI 正在读取商品页 · 页/秒** | 「爬虫」「抓取」是技术词 |
| 接入店铺 | **已接入的店铺** | — |
| 全球引荐分布 | **顾客来自哪里** | — |
| 按引荐渠道 | **来自哪个 AI 助手** | 这一格是**按渠道拆开看**，不是归因，所以去掉「带来的」只留「来自」 |
| 按市场 | **按国家 / 地区** | 「市场」不如「国家」直接 |
| AI 引荐订单流 | **Agentic Page 带来的订单** | 同成交额那条 |
| **边缘抓取日志** | **AI 正在读取你的商品页** | 「边缘」是 CDN 术语，商家完全看不懂 |
| 稀有度（普通/较大/大额/特大） | **订单规模**（值不变） | 「稀有度」是游戏术语（rare/epic） |
| 市场列 `US` / `JP` | **美国 / 日本** | 屏上已无别处需要代码，代码就成了负担 |
| 来源列 `Others` | **其他 AI** | — |
| 爬虫列 `GPTBot` | **ChatGPT** + 灰色小字 `GPTBot` | 品牌名商家认得；程序名留着当真实感 |
| 状态列 `200` / `304` | **已读取** / **内容未变** | 304 Not Modified 的语义就是「上次读过、内容没变」，这对商家是有意义的信息 |
| 里程碑「AP 翻译页面突破 N 页」 | **已有 N 个商品页可被 AI 读懂** | 「翻译页面」是我们的产品动作名 |

## 清掉了什么（按类型）

| 类型 | 清掉的内容 |
|---|---|
| **版面注解**（我写给自己看的） | `今日汇总 · 三项配角指标`、`行高 49px · 真实值未放大` —— 这是设计说明，绝不该上屏 |
| **暴露实现** | `占比基于取样 59 笔 + 实时 N 笔`、`采样 9/秒 · 实际 49.7/秒`、`全精度不四舍五入` —— 商家读成「你这数据是估的？」 |
| **内部工程语** | `环境 生产`、`数据流正常`、`刷新 1s`、`运维`头像、`来源 IP`、`ASN`、`大小 kB` |
| **内部操作** | 顶栏的「主题」控件、右下角的 `? 快捷键 T 换主题` |
| **英文装饰** | `LIVE MAP` / `BY REFERRER` / `BY MARKET` / `TRADE PRINTS` / `EDGE ACCESS LOG` —— 内部术语的英文，不是通用词 |

## 一个必须说清的取舍

调研结论说「真实感来自系统家具（字段名、状态码、ASN 这类工程痕迹）」。
这一轮为了商家能看懂，把 `ASN` / `来源 IP` / `200`/`304` 这些都换掉了 ——
**真实感的承担者因此换了一批**：

| 现在靠什么撑真实感 | 商家能不能验证 |
|---|---|
| 他自己的商品页 URL（`/products/brushed-oak-chore-jacket`） | **能** —— 那就是他店里的路径 |
| 真实的 AI 程序名（`GPTBot` / `Google-Extended` / `ClaudeBot`） | **能** —— 看过自家 access log 的商家会认出来 |
| 带毫秒的时间戳（`21:17:00.472`） | 能感知「这是机器写的，不是排版出来的」 |
| 读取来源地（London / Mumbai / Sydney） | 能 —— AI 从全球各地来读他的店 |
| 响应耗时（`242ms`） | **能，而且对他有用** —— 自己店响应快不快 |
| 「内容未变」这种带语义的结果 | 能 |

换掉的是**商家读不出来的那部分工程痕迹**，留下的是**他能对上号的那部分**。
这比堆 ASN 更能让他相信 —— 因为他可以拿自己的店去核对。

## 左下角的扫码抽奖入口

收起态是一枚小标（不抢画面）→ **悬停**浮起并出提示 → **点击**展开二维码卡。
也可以按 **`Q`** 开合、`Esc` 关闭 —— 展会现场多半没鼠标，操作员需要键盘入口。

二维码指向问卷 H5（`../E-survey/`），**现场生成，零网络依赖**：
`qr.js` 是自己写的最小 QR 编码器（字节模式 · 版本 1~6 · 纠错等级 M），
因为展会屏不能调任何在线二维码接口，本机也没有可用的库。

| 项 | 值 |
|---|---|
| 二维码内容 | `http://<局域网IP>:8099/E-survey/`（35 字节） |
| 规格 | 第 3 版 **29×29 模块**，白底深码 |
| 为什么只做 1~6 版 | 版本 ≥7 要多写一块「版本信息」；更关键的是**版本越低模块越少 → 屏上每个模块越大 → 越好扫**（3 版 29×29，6 版 41×41，同尺寸下模块大 40%） |
| 地址怎么来 | **大屏用局域网 IP 打开时自动沿用同一 host**，操作员不用改代码；用 `localhost` 打开时退回 `app.js` 里的 `SURVEY_FALLBACK` 常量 |

### 编码器是交叉校验过的（这一步逮到了一个致命 bug）

第一版写完后结构自检全过（定位图形、定时图形、固定黑点都对），**但其实扫不出来**。
用本机另一份独立实现（Kazuhiko Arase 的 QRCode，久经检验）逐格比对才发现：
**我把格式信息的横向与竖向两份拷贝写反了** —— 标准是 bit0~5 走第 8 **列**，我写成了第 8 **行**。
后果是数据区完全正确、只有 12 个格式信息模块错，于是扫描器读不到掩码编号，整张码作废。

修好后的校验结论：**8 个用例覆盖 1~6 版，每一个都存在某个掩码使全部模块与参考实现逐格一致**
（441 / 841 / 1089 / 1369 / 1681 格）。

> 两处与参考实现**故意不同**，不是 bug：
> ① 掩码选择：参考实现的规则 1 惩罚分是「数 8 邻域同色个数」（Arase 库的著名非标准偏差），
>   我按的是 ISO/IEC 18004 的「数行列上 5 连以上的段」。两者都产出合法可扫的码。
> ② 非 ASCII：参考实现用 `charCodeAt` 截 8 位，**没做 UTF-8**；我按 UTF-8。
>   我们的内容是纯 ASCII 的 URL，不受影响。

### 一个位置上的取舍

入口在屏幕左下角（按要求），那里正好压住**订单流最后一行**的左端。
这是所有位置里最便宜的一处遮挡：**最新的订单在最上面，最下面那行是最旧的**。
展开的卡片（430×325）会盖住订单表左半边几秒 —— 那是操作员主动触发的瞬时交互，可以接受。

## 主题切换（五套，操作员可用）

按 `T` 循环。**屏上没有入口**（挑配色是内部的事），切换的反馈就是整屏变色本身。
选择存 `localStorage`，刷新保留。`APDiag.setTheme(0..4)` 可脚本切换。

| `p2` | 暖墨陶土 | 方案 C 原版的 P2 | `#6A8E7F` / `#D97757` |

## 动效

- **订单入场**取**方案 C 原版**：环形缓冲 + 整表 `translate3d` 下移 260ms
  `cubic-bezier(.22,1,.36,1)`，新行**逐格 split-flap 揭示**（stagger 21/26ms，
  每格按字符类别翻 3~5 次 × 46/54ms）
- **订单强调**取 **C-LED 中文版**：3px 左标记条 + 整行高亮 + 大额转红。不做点阵/发光/霓虹
- **高亮时序**按 03 线实测的 ag-grid 业界值：**保持 500ms + 淡出 900ms → 静息 3%**
- **读取日志**：渐入 320ms + 按行龄渐隐 + 底部蒙版
- **成交额跳动**做成事件：引擎的 `gmv` 是按订单游标的阶梯函数（约一分钟跳一次），
  不做连续爬升（那等于凭空造出没发生的钱），改成跳动时浮一个 `+$962.18`

## 引擎事实（踩过才知道的）

1. **`APEngine.dt()` 返回毫秒**（就是 `_dtMs`），不是秒。按秒再乘 1000 会让每帧虚拟推进
   16.7 秒，**一个单位错误同时废掉四处动效**：翻牌一帧走完、地图打点当帧即灭、
   横幅闪一帧、fps 算成 0。
2. **`triggerOrder` 收的是 `{usd}` 对象**，不是位置参数。传位置参数会退回引擎的
   `forceBig` —— 那条路中位数只有约 $310 而 epic 门槛正好 $300，于是「B 键一半时间不出大单」。
3. **`peekOrders(n)` 有 62 笔硬上限**：传 200 / 600 / 1500 / 4000 得到的都是同一批 62 笔。
   所以预铺**不能写死偏移量**，必须按实际返回长度取尾部（取头部会被 id 去重挡掉，
   订单流会冻住好几分钟）。
4. **按国家的基数不能靠取样估**：金额是重尾分布，62 笔取样会让权重 6 的加拿大掉到 1%。
   改用 `APGeo.MARKETS` 自带的 `weight` 算基数（权威值），增量走真实订单。
5. **`APGeo.CITIES` 是数组的数组** `[名称, 纬度, 经度, 国家码, 权重]`，按对象属性取 `cc` 全落空。
6. **时间戳两个方向都要对**：间隔必须累加；且 `pushOrder` 是顶部插入，所以**最后**推的
   必须是**最近**的一笔。写反会出现「越往下越晚」。

  展会机没中文音色就是哑的 —— 仍是 P1 第一优先
- `K` 里程碑只出横幅，没有 split-flap 齐翻

- 没进总入口 `index.html` 的卡片
- **屏上已无任何「模拟演示数据」标注**（按要求移除）。启动遮罩上也已去掉。
  一张截图外传时，读者眼里就是真实业绩 —— 这条风险由业务方承担
