# 方案 E · 运营监控台（动态版 · 第一稿）

> **平行版本，不替代任何现有方案。** A/B/C/D 与 C-LED 两版全部原样保留。
> 打开：`启动预览.bat` 后开 `http://localhost:8099/E-运营监控台/index.html`，或双击 `index.html`。
> 进来先点「点击进入」（规格 §6 的启动遮罩，同时解锁声音）。

## 这一版是什么

「中间态」路线的第一个**能跑**的原型 —— 传播感与后台感**分带并置**，不是折中平均。
它不是从零设计的，每一处都指向一个已经量过的来源：

| 部件 | 取自 | 具体值 |
|---|---|---|
| 底色 / 面板 / 描边 | 02 线对 Grafana 的 `getComputedStyle` 实测 | `#111217` / `#181b1f` / `#2e3036`，面板比底亮、纯黑只当缝 |
| **全局主题色** | **方案 A 的两个强调色** | 青绿 `#00D3A7` 爬虫层（冷强调，也是全局主题色）+ 暖金 `#FFB86B` 订单层（暖强调，稀有出现） |
| 抓取日志样式 | **方案 A 右半边** `EDGE ACCESS LOG` | 9 列等宽、密到贴边、带 ASN 与时延、状态码混着 304、IP 脱敏成 `x.x`；另加渐入 + 按行龄渐隐 + 底部蒙版 |
| 订单流**入场动画** | **方案 C 原版** | 环形缓冲 + 整表 `translate3d` 下移 260ms `cubic-bezier(.22,1,.36,1)`，新行**逐格 split-flap 揭示**（stagger 21/26ms，每格翻 3~5 次 × 46/54ms，字符按类别置换） |
| 订单流**强调样式** | **C-LED 中文版** | 3px 左标记条 + 整行高亮 + 大额转红。**不做点阵、不做发光、不做霓虹** |
| 焦点公式 | 01 线对 Shopify Live View 的像素实测 | 主角不靠字号（27px vs 26px），靠字重 1.7 倍 + 标签在上 + 归组降权 |

## 两处刻意的偏离，都记在这里

1. **§4.3 要求「一个绝对主角」，本版放了两个同样大的指标。** 按需求把累计成交额与累计爬取次数
   并列，用**色相**（暖金 / 青绿）+ 语义分工区分，不用尺寸。代价是严格意义上没有单一焦点。

2. **累计成交额是离散的，不做连续爬升。** 引擎的 `gmv` 是按订单游标的阶梯函数
   （`CONFIG.GMV0 + 已到达订单的 usd 之和`），1.06 单/分，约一分钟才跳一次。
   给它做连续爬升等于凭空造出没发生的钱。改成把**跳动本身做成事件**：
   一笔单进来时在数字右侧浮一个 `+$962.18`，和订单行入场同时发生 ——
   读起来就是「这一行让那个数字跳了」。同 BFCM「Every particle is a real order」的思路。
   连续在动的是**爬取次数**（44/秒），那一格本身就够活。

## 一处对 C-LED 第四版的修正

第四版的新行高亮是 **480ms 线性、没有保持段**，一闪即没像故障。
03 线实测交易台通用表格库 ag-grid 的记录值是「**保持 500ms + 淡出 1000ms**」。
本版按业界值重定：**500ms 满亮保持 + 900ms 淡出 → 静息 3%**（`@keyframes hlfade`）。
「整行 vs 单格」没抄 ag-grid —— 单格高亮在 3 米外看不见，整行是我们观看距离下的正解。

## 这一稿踩到的四个坑（写清为什么）

1. **`APEngine.dt()` 返回的是毫秒**（引擎里就是 `_dtMs`），不是秒。
   我按秒又乘了 1000 → 每帧虚拟推进 16.7 秒，于是**一个单位错误同时废掉四处动效**：
   翻牌一帧走完、地图打点当帧即灭、横幅闪一帧、fps 算成 0。
   参照写法见 C-LED 第四版：`var dtMs = E.dt(), dtS = dtMs / 1000;`

2. **`triggerOrder` 收的是 `{usd}` 对象，不是位置参数。** 传 `(460, 1280)` 会被当成
   `opts = 460`、`opts.usd = undefined`，退回引擎的 `forceBig` —— 那条路中位数只有约 $310，
   而 epic 门槛正好 $300，所以「B 键约一半时间不出大单」。必须显式给 `{usd: 460~1280}`。

3. **预铺不能取「最近的 N 笔」。** 只加 id 去重的话，那 N 笔真实到达时全被挡掉，
   屏上「订单流冻住」好几分钟（实测开场 6 笔全被吃掉，gmv 在跳但行不换）。
   解法：取**远期**的 N 笔（第 58~63 笔，约 55 分钟后才到）+ id 去重兜底。

4. **时间戳有两个方向要同时对**：间隔必须**累加**（C-LED 第四版的原话），
   而且赋值方向要让**最后推的那一行是最近的一笔** —— `pushOrder` 是顶部插入。
   第一轮写反了，屏上出现 `19:33:24 / 19:27:32 / 19:28:35 ……` 越往下越晚。

顺带两个不是本项目的坑：`APGeo.CITIES` 是**数组的数组** `[名称, 纬度, 经度, 国家码, 权重]`，
按对象属性取 `cc` 会全部落空；`getBoundingClientRect` 取块级元素会返回整格宽度，
拿它判断「有没有压到数字」必然误报（`.big` 已改 inline-block）。

## 还没做的

- **没接声音的实听**：`APAudio` 已按 API 接上（`playOrder` / `playMilestone` / `unlock` /
  静音 / 环境音 / 展馆模式），但**一次都没真听过**。人声仍靠浏览器 `speechSynthesis`，
  展会机没中文音色就是哑的 —— 这条仍是 P1 第一优先。
- **里程碑齐翻没做**：`K` 键目前只出横幅，没有 split-flap 齐翻。
- **地图打点上限 90、按 5/秒限流**，10 小时长跑没压测过。
- **真机帧率没量过**（headless 不按 60Hz 驱动 rAF；真机开页面看 `window.APDiag.fpsAvg`）。
- **没进总入口 `index.html`** —— 需要的话给它加一张卡片。
- 「按市场」面板在这一版被地图挤掉了（地图要占两张卡宽）。数据还在引擎里，随时能加回来。

## 自检口

```js
APDiag.fpsAvg        // 帧率（真机上看这个）
APDiag.dom           // DOM 节点数，应恒定
APDiag.hits          // 地图活动打点数
APDiag.seen          // 已入场订单数（去重后）
APDiag.topOrder      // 最新一行订单的内容（环形缓冲位置是转的，别靠 querySelector 取第一个）
APDiag.topLog        // 最新一行日志
APDiag.metrics()     // 引擎指标快照
```
