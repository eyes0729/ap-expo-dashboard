NEW钱到账的声音（你这次要的）

先说清一件事：支付宝那个声音本身不是硬币，是一个干净的双音提示音。你说的「钱袋入金感」其实来自提示音 + 人声这个组合，不是音色里真的有钱币。所以下面四条里，「到账」那条最接近支付宝，而「哗啦 / 入袋」是真的硬币声——更直白，但每 2.4 分钟响一次会不会烦，要你听了定。

硬币声是怎么合成的：不是"叮"一声正弦波。一枚硬币是 极快的撞击瞬态 + 薄圆盘的非谐振动模式（频率比约 1 : 1.73 : 2.41 : 3.17）。 这一条是关键——用整数泛音会立刻听成"钟"，不是硬币。 一把硬币则靠密度曲线：前 120ms 冲到最高再指数拖尾； 匀速散布听起来像下雨，不像倒钱。 每枚的音高/时刻/声像都由固定种子的伪随机给出，所以可复现， 换个种子就是新的一把——不会像采样库那样两次播放一模一样、很快被听出是循环。

NEW更像真人：用一句中文指令控制情绪

你说的「太机械化」，我先确认过不是退回旧音色——大屏现在播的确实是神经语音（voiceSource="pack"）。所以问题不在音质，在Xiaoxiao 是新闻播音腔：平、稳、没有情绪起伏。而「到账」要的是一点惊喜和确认感，那是情绪。

2026 年的中文 TTS 已经从「念文本」走到「理解后表达」。下面是本机 CosyVoice2 用自然语言指令生成的——免费、离线、一句中文就能换语气。

⚠ 这些样本有一个硬伤，必须先说：时长 5.8~7.9 秒，而现在用的 Xiaoxiao 是 3.1 秒。 播报平均 2.4 分钟一条，6 秒本身不算长；但宏节拍那 10 分钟一次的齐发会有 3~5 单挤在一起， 6 秒的播报会互相盖住。指令模式让模型"演"，它就会拖长——这是取舍，不是 bug。

真要用，两条路：① 生成时给 speed=1.3（会损失一点自然度） ② 把句子改短（去掉「Agentic Page 店铺」只留「到账，一千二百八十美元」）。 建议先只听语气、别管长度——先定要不要这个方向，定了我再压时长。

04关键对比：拼接 vs 整句

这一条和音色无关，是做法的问题——而且它是现在这套素材真正的隐患。_voice/stitch.js 把金额切成「一千」「二百」「八十美元」分别合成、运行时拼起来。每个片段单独合成时模型都会给它一个句尾降调，三个降调连着出现就是「报电话号码」的听感。项目自己的 README 早就写了「不要做数字拼接」，但 stitch.js 做的正是拼接。

顺带说清一件事：我试过用基频范围/跳变率去客观量化「机械 vs 自然」，量不出来—— Huihui 的基频范围 13.3 半音、跳变率 4.0%，四组数字互相咬在一起，分不出高下。 原因是 Huihui 属于单元挑选式拼接，用的是真人录音片段，所以基频本身是真人的； 它难听在单元接缝处的频谱突变和整句韵律错，这两样我那两个指标都测不到。 所以这一页不给你看分数，只能靠耳朵定。唯一有参考价值的客观数是时长（见各卡片）。

08不管选哪个音色，这件事都要改

整句预渲染，别再拼接。我把引擎跑了一遍数出来了——引擎是时间的纯函数，所以一场展会会播哪些金额是可以提前算出来的：
口径数量说明
一天(9h) 订单总数575 单—
达到播报门槛(≥$110)228 条平均 2.4 分钟一条，和 README 写的一致
不同金额（去重）166 个一天
不同金额（去重）375 个4 天展期累计
整句预渲染体积45MBWAV；压成 mp3/opus 约 4.5MB
也就是说：整个展期只要 375 条整句音频，4.5MB。拼接省下来的那点体积毫无意义， 却换来了「三个句尾降调连着出现」这个听感缺陷。

唯一的例外是 B 键（BD 手动触发大单）——它是全代码里唯一用 Math.random() 的地方， 金额不可预知。建议把它改成在一组预先渲染好的漂亮大额里轮换（$1,280 / $2,460 / $3,880 …）： 既能全量预渲染，BD 也不会再抽到一个不好看的数字。
